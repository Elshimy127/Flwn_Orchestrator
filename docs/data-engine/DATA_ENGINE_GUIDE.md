# Using the Data Engine from the Orchestrator

How the orchestrator calls the data engine's CRUD API: how to connect, the conventions, the errors, the **business rules the orchestrator must enforce itself**, and the common flows.

| File (this folder) | What it is |
|---|---|
| `DATA_ENGINE_GUIDE.md` | this guide: read it first |
| `API_REFERENCE.md` | every endpoint and every field (generated, don't edit) |
| `data-engine-openapi.json` | the machine-readable contract: generate the client from it |
| `generate.py` | regenerates the two files above when the data engine changes |

> Source: `flwn-data-engine`, branch `feature/schema-and-basic-cruds` (55 domain routes). The Postman collection in `flwn-data-engine/docs/postman/` shows every call working end to end.

---

## 1. Who does what

```
Frontend / agents ──► Orchestrator ──HTTP──► Data Engine ──► Postgres
                     (business rules)        (data rules only)
```

| The data engine does | The orchestrator does |
|---|---|
| store, read, update, delete rows | decide **who** may do **what** (permissions) |
| validate data: types, lengths, enums, required fields | decide **when** something is allowed (workflow, status transitions) |
| enforce references: same organization, same project | check membership: "is this user in this org / on this project?" |
| enforce uniqueness and DB rules (one ACTIVE sprint per team, DONE ⇔ completedAt) | compute values like `completedAt` |
| keep tenants apart (another org's row → 404) | choose the organization for each call, **from the verified session** |
| return archived rows as normal data | decide whether archived things are shown, or changed |

**Rule of thumb:** if the data engine accepts something, it's *valid data*. That doesn't make it *allowed*. Allowed is the orchestrator's call.

## 2. Connecting

| Setting | Value |
|---|---|
| Base URL | `http://<data-engine-host>:8002` (locally `http://localhost:8002`) |
| Auth header (every request) | `X-Data-API-Key: <secret>`, the same value as `DATA_API_KEY` in the data engine's `.env`. Keep it in the orchestrator's config or secrets, **never** in code or in git. |
| Content type | `application/json` |
| Network | keep the data engine on a **private network**, with TLS outside local dev. Only the orchestrator should be able to reach it. |
| Interactive docs | `GET /docs` (Swagger), `GET /openapi.json` |

Missing or wrong key → `401 {"detail": "Invalid data API key"}`. That's the only error that **doesn't** use the standard error shape (§5).

### 2.1 The organization of each request (tenant scoping)

| Route starts with | Organization comes from | Example |
|---|---|---|
| `/organizations/{orgId}/…` | the URL; **no** header needed | `GET /organizations/{orgId}/members` |
| `/users…`, `POST /organizations` | nothing: these are global | `GET /users?email=…` |
| anything else | the header **`X-Organization-Id: <uuid>`** | `GET /tasks/{taskId}` |

- Missing header → `400 ORGANIZATION_ID_REQUIRED`. Header not a UUID → `422 VALIDATION_ERROR`.
- A row that belongs to **another** organization behaves as if it doesn't exist: `404 <ENTITY>_NOT_FOUND`.

> ⚠️ **Tenant safety is the orchestrator's responsibility.** The data engine trusts `X-Organization-Id` because only the orchestrator holds the API key. So **always take the org id from the user's verified session**, after checking the user is a member of that org (`GET /users/{userId}/memberships`). **Never** forward an org id that came from the client.
>
> ```go
> // ❌ orgID := r.Header.Get("X-Organization-Id")     // user-controlled
> // ✅ orgID := session.CurrentOrganizationID         // set at login, membership verified
> ```

## 3. Conventions

| Topic | Rule |
|---|---|
| JSON keys | **camelCase** in both requests and responses (`createdById`, `acceptanceCriteria`) |
| IDs | UUID strings, generated by the data engine. **Never send `id`** when creating. |
| Parent ids | come from the **URL**, never the body. To create a task, call `POST /projects/{projectId}/tasks`, with no `projectId` in the body. |
| Server-owned fields | never sent: `id`, `organizationId`, `createdAt`, `updatedAt`, `joinedAt`, `archivedAt`, `number` |
| Fields that can't change | `organizationId`, a team's or project's `workspaceId`, `projectId`, every `createdById`, `Member.userId`, `Member.type`, `Project.key`, `Task.number`, `Sprint.teamId`. They aren't in the Update schemas; sending them gives `422`. |
| Unknown fields | rejected with `422`, field = the unknown key. A typo fails loudly. |
| Text | trimmed. A blank required text gives `422`; an optional text sent as `""` is stored as `null`. |
| Date-times (`dueDate`, `completedAt`) | **must include a timezone** (`2026-11-03T17:00:00Z` or `+03:00`); a naive value gives `422`. Stored and returned in UTC. |
| Dates (`Sprint.startDate/endDate`) | `YYYY-MM-DD`, no time |
| Enums | exact UPPERCASE values: `IN_PROGRESS`, not `in progress` |
| Emails | stored lowercase; lookups ignore case |
| Success codes | `POST` 201 · `GET` 200 · `PATCH` 200 · `DELETE` 204 (empty body) |

### 3.1 PATCH (partial update)
- Send **only** the fields you want to change. Fields you leave out are untouched.
- Sending `null` **clears** a nullable field (e.g. `{"assigneeId": null}` unassigns). For a required field, `null` gives `422`.
- An empty body `{}` is a no-op that returns 200 with the current row.

### 3.2 Archive and restore (organizations, workspaces, projects, teams)
- `DELETE` on these **archives**: it sets `archivedAt`. Nothing is removed.
- **Restore** with `PATCH {"archived": false}`.
- **Archived rows are still returned** by every GET and list. List routes accept `?archived=true|false`; with no filter, everything is returned. **You decide what to show.**
- ⚠️ Archiving a project does **not** mark its tasks or sprints. To know whether a task is effectively archived, check its **project's** `archivedAt`. The same goes for anything under an archived workspace or organization.
- The data engine **allows** creating things under an archived parent. Block that in the orchestrator if you don't want it.

### 3.3 What DELETE does, per entity

| Entity | `DELETE` means |
|---|---|
| Organization, Workspace, Project, Team | archive (soft) |
| User, Member | **no DELETE**. Users are permanent; deactivate a member with `PATCH {"status": "INACTIVE"}`. |
| WorkItem | hard delete; its tasks remain, with `workItemId: null` |
| Sprint | hard delete; its tasks go back to the backlog (`sprintId: null`) |
| Task | hard delete. Its number is **never reused**. |
| TeamMember, ProjectTeam | hard delete (unlink). A ProjectTeam can't be removed while that team has sprints in the project (`409 PROJECT_TEAM_HAS_SPRINTS`). |

### 3.4 Pagination
Every list returns:
```json
{ "items": [ ... ], "limit": 50, "offset": 0, "hasMore": true }
```
- Query: `limit` (1–200, default 50) and `offset` (≥ 0).
- There's **no total count**; use `hasMore` for "load more" or infinite scroll.
- Order is stable: tasks by `number`; everything else by `createdAt`, then `id`.

To read everything (e.g. for a background job):
```go
for offset := 0; ; offset += limit {
    page := client.ListTasks(ctx, projectID, limit, offset)
    handle(page.Items)
    if !page.HasMore { break }
}
```

### 3.5 Task keys (`FLWN-12`)
- Every task has a per-project `number` (1, 2, 3…) assigned by the data engine, and a `key` = `Project.key` + `-` + `number`.
- Look a task up by key: `GET /tasks/by-key/FLWN-12` (within the header's org). Use this for branch names, commit messages, chat ("take FLWN-12") and meeting notes.
- `Project.key` is 2–10 uppercase letters, unique per organization (archived projects included), and **can't change**.

## 4. Domain model (quick map)

```
User (global login account)
  └──< Member (membership in one organization; AI members have no User)

Organization
  ├──< Member      (role OWNER | MEMBER, status ACTIVE | INACTIVE, optional home department)
  └──< Workspace   (= department: Software, HR…)
          ├──< Team ──< TeamMember (role LEAD | MEMBER) >── Member   (any department, same org)
          └──< Project (owning department, key e.g. FLWN)
                  ├──< ProjectTeam >── Team                 (teams from any department, same org)
                  │        └──< Sprint                      (a team's sprint in this project)
                  ├──< WorkItem   (optional grouping: FEATURE | STORY | BUG)
                  └──< Task       (FLWN-12; optional workItem, sprint, assignee)
```

- **Project access is through teams:** a member's projects are their teams' projects (`GET /members/{id}/projects`).
- **The backlog** = a project's tasks with no sprint (`GET /projects/{id}/tasks?backlog=true`).
- **Human vs AI member:** a HUMAN has `userId`, and its `name`/`email` come from the User. An AI has no `userId`, a required `name` (unique per org) and an optional `email`.

## 5. Errors

Every domain error has this shape:
```json
{ "code": "SPRINT_ALREADY_ACTIVE", "message": "Already exists", "field": "status" }
```
- Branch on **`code`**, never on `message` (messages are generic and may change).
- `field` is the camelCase request field involved, or `null`. Use it to point the user at the right input.

| HTTP | `code` | Meaning | Typical orchestrator reaction |
|---|---|---|---|
| 400 | `ORGANIZATION_ID_REQUIRED` | the header is missing | **orchestrator bug**: log it and return 500 |
| 401 | *(`{"detail": …}`)* | wrong or missing API key | config problem: log and alert |
| 404 | `<ENTITY>_NOT_FOUND` | the id doesn't exist **or** belongs to another org | 404 to the client |
| 409 | `USER_ALREADY_EXISTS` | email already used | "email already registered" |
| 409 | `MEMBER_ALREADY_EXISTS` | user already in the org, or AI name/email taken (see `field`) | 409 with that field |
| 409 | `WORKSPACE_ALREADY_EXISTS` / `TEAM_ALREADY_EXISTS` / `PROJECT_ALREADY_EXISTS` | name taken (case-insensitive, among non-archived rows) | "name already used" |
| 409 | `PROJECT_KEY_ALREADY_EXISTS` | project key taken in the org (archived included) | "choose another key" |
| 409 | `SPRINT_ALREADY_EXISTS` | sprint name taken for this team in this project | "name already used" |
| 409 | `SPRINT_ALREADY_ACTIVE` | the team already has an ACTIVE sprint in this project | "finish the current sprint first" |
| 409 | `TEAM_MEMBER_ALREADY_EXISTS` / `PROJECT_TEAM_ALREADY_EXISTS` | the link already exists | treat as idempotent, or report a conflict |
| 409 | `PROJECT_TEAM_HAS_SPRINTS` | removing a team that still has sprints in the project | close or move its sprints first |
| 409 | `TASK_NUMBER_CONFLICT`, `CONFLICT` | defensive internal mappings; shouldn't happen | log as unexpected, 500 |
| 422 | `VALIDATION_ERROR` | bad type, length, enum, unknown field, missing timezone, or a broken data rule (`completedAt` without DONE, `endDate` before `startDate`, name/email on a HUMAN member…) | if the input came from the user: 422 with `field`; if your code built it: a bug |
| 422 | `INVALID_REFERENCE` | an id in the **body** doesn't exist, belongs to another org, or crosses a project (e.g. `sprintId` from another project) | 422 with `field` |
| 500 | `INTERNAL_ERROR` | unexpected | log, 500, maybe retry reads (§6) |

## 6. Reliability

| Situation | Advice |
|---|---|
| Timeouts | set a client timeout (e.g. 5–10 s) |
| Retrying **GET** | safe on network errors and 5xx |
| Retrying **POST** | ⚠️ **not idempotent.** A timeout may mean the row **was** created; retrying can create a duplicate task (with a new number). Before retrying, check by reading (e.g. list the latest tasks), or surface the error. |
| Retrying **PATCH / DELETE** | usually safe (the same result if repeated). A second DELETE of a link gives 404. |
| Retrying 4xx | never. The request itself is wrong. |
| Atomicity | **each call is one transaction.** A multi-step flow in the orchestrator (e.g. create project, then add teams, then create a sprint) is **not** atomic across calls. Design flows so a partial failure is harmless, or clean up. The one built-in exception: `POST /organizations` creates the org **and** its owner member together. |
| Races | the data engine guarantees data rules under concurrency (unique task numbers, one ACTIVE sprint). Business checks the orchestrator does *before* writing (e.g. "is the assignee on the project?") can race with a change in between. That's acceptable for the MVP. |

## 7. Business rules the orchestrator must enforce

The data engine **will accept** all of these. Only the orchestrator stops them.

| # | Rule | How to check, using the data engine |
|---|---|---|
| B1 | The caller is a member of the organization they act in | `GET /users/{userId}/memberships`, then pick the org from the session |
| B2 | Permissions, e.g. only an `OWNER` creates departments, adds members or archives | `GET /members/{memberId}` → `role` |
| B3 | An organization keeps at least one `OWNER` | before demoting or deactivating an owner: `GET /organizations/{orgId}/members?role=OWNER&status=ACTIVE` |
| B4 | **An assignee must be on one of the project's teams** | `GET /members/{assigneeId}/projects` contains the project, or compare `GET /projects/{id}/teams` with `GET /members/{id}/teams` |
| B5 | Don't assign tasks to an `INACTIVE` member | `GET /members/{id}` → `status` |
| B6 | Allowed task status transitions (e.g. REVIEW before DONE) | read the task, check the transition |
| B7 | Moving to `DONE`: **send `completedAt`** (now, UTC). Moving away from DONE: send `completedAt: null`. | otherwise `422 VALIDATION_ERROR` (field `completedAt`) |
| B8 | A sprint can't become `ACTIVE` with 0 tasks | `GET /projects/{id}/tasks?sprintId={sprintId}&limit=1` |
| B9 | No new work under an archived organization, department or project (if that's the product decision) | check the parent's `archivedAt` before creating |
| B10 | Hide archived items where the UI expects that | `?archived=false`, or filter on `archivedAt` |
| B11 | Only humans log in; AI members (no `userId`) act through agents | `Member.type` |
| B12 | Agents may **read** domain data but must **not** write it directly; writes go through the orchestrator | agent access is not built yet (see §10) |

## 8. Common flows

All bodies are camelCase JSON. "`[org]`" means *send `X-Organization-Id`*.

### 8.1 Sign-up and create an organization
```
POST /users                         {"name": "Ahmed", "email": "ahmed@acme.io"}         → 201 UserRead
POST /organizations                 {"name": "Acme", "createdById": "<userId>",
                                     "creatorMember": {"role": "OWNER"}}                → 201 {organization, member}
```
`creatorMember` is optional and defaults to OWNER. If the user doesn't exist, you get `422 INVALID_REFERENCE` and **nothing** is created.

### 8.2 Login: which organizations is this user in?
```
GET /users?email=ahmed@acme.io                          → page with 0 or 1 user
GET /users/{userId}/memberships                         → the user's Members, one per org (with organizationId, role, status)
```
Store the chosen `organizationId` and `memberId` in the session (B1).

### 8.3 Departments, teams, people
```
POST /organizations/{orgId}/workspaces   {"name": "Software", "createdById": "<memberId>"}
POST /workspaces/{workspaceId}/teams  [org]  {"name": "Backend", "createdById": "<memberId>"}
POST /organizations/{orgId}/members      {"type": "AI", "name": "Ghost", "createdById": "<memberId>"}         (AI employee)
POST /organizations/{orgId}/members      {"type": "HUMAN", "userId": "<userId>", "createdById": "<memberId>"}  (invite an existing user)
POST /teams/{teamId}/members  [org]      {"memberId": "<id>", "role": "LEAD"}                                  (role defaults to MEMBER)
```

### 8.4 Project with teams (cross-department allowed)
```
POST /workspaces/{workspaceId}/projects  [org]  {"key": "FLWN", "name": "Flwn", "createdById": "<memberId>"}
POST /projects/{projectId}/teams          [org]  {"teamId": "<backendTeamId>"}
POST /projects/{projectId}/teams          [org]  {"teamId": "<recruitingTeamId>"}     (team from HR: OK)
```

### 8.5 Sprint planning
```
POST /projects/{projectId}/teams/{teamId}/sprints  [org]
     {"name": "Sprint 1", "startDate": "2026-11-01", "endDate": "2026-11-14", "createdById": "<memberId>"}
GET  /projects/{projectId}/tasks?backlog=true      [org]              (pick tasks)
PATCH /tasks/{taskId}                               [org]  {"sprintId": "<sprintId>"}
-- B8 check, then:
PATCH /sprints/{sprintId}                           [org]  {"status": "ACTIVE"}       (409 SPRINT_ALREADY_ACTIVE if the team has one)
```

### 8.6 Create and assign a task
```
-- B4/B5 checks on the assignee first
POST /projects/{projectId}/tasks  [org]
     {"title": "Fix token refresh", "acceptanceCriteria": "…", "assigneeId": "<memberId>",
      "dueDate": "2026-11-03T17:00:00Z", "createdById": "<memberId>"}     → 201 TaskRead with number + key (FLWN-13)
```

### 8.7 Move a task to DONE
```
-- B6 transition check, then:
PATCH /tasks/{taskId}  [org]  {"status": "DONE", "completedAt": "<now, UTC>"}
```

### 8.8 "My work" screens
```
GET /members/{memberId}/projects            [org]      projects through my teams (US-16)
GET /members/{memberId}/tasks?status=TODO   [org]      my tasks across projects (US-18)
GET /members/{memberId}/teams               [org]
GET /projects/{projectId}/tasks?status=IN_PROGRESS&assigneeId=…  [org]   board column / filters
GET /tasks/by-key/FLWN-13                   [org]      from a branch name, commit or chat
```

### 8.9 Archive and restore a project
```
DELETE /projects/{projectId}                [org]  → 204
GET    /workspaces/{workspaceId}/projects?archived=false  [org]    (it's gone from the active list)
PATCH  /projects/{projectId}                [org]  {"archived": false}    (restore)
```

## 9. Generating the Go client

`data-engine-openapi.json` is OpenAPI 3.1 and contains only the domain routes. With **oapi-codegen**:
```sh
go install github.com/oapi-codegen/oapi-codegen/v2/cmd/oapi-codegen@latest
oapi-codegen -generate types,client -package dataengine \
    docs/data-engine/data-engine-openapi.json > internal/dataengine/client.gen.go
```
Then wrap it once, so the rest of the orchestrator never sets headers by hand:
```go
// Every request gets the API key; org-scoped calls get the session's org.
apiKey := func(ctx context.Context, req *http.Request) error {
    req.Header.Set("X-Data-API-Key", cfg.DataEngineAPIKey)
    if orgID, ok := OrgFromContext(ctx); ok {          // set from the verified session (B1)
        req.Header.Set("X-Organization-Id", orgID.String())
    }
    return nil
}
client, _ := dataengine.NewClientWithResponses(cfg.DataEngineURL, dataengine.WithRequestEditorFn(apiKey))
```
Decode non-2xx bodies into `ErrorResponse{Code, Message, Field}` and branch on `Code` (§5).

> oapi-codegen's OpenAPI 3.1 support has gaps (mostly `anyOf` with `null` for nullable fields). If generation complains, convert the file to 3.0 first, or hand-write the few types you need. The field tables in `API_REFERENCE.md` are the source of truth either way.

## 10. Known limitations (current data engine)

| Limitation | Impact on the orchestrator |
|---|---|
| Unknown paths and methods return `401 {"error":"invalid_token"}` instead of 404/405 (the MCP app is mounted at `/`) | a 401 with `invalid_token` usually means **a wrong URL or method**, not a bad key. It will be fixed in the agent step. |
| No agent access to domain routes yet | agents go through the orchestrator for now |
| No total counts on lists | use `hasMore` |
| No search (by name or title) and no bulk endpoints | filter by the documented query params only; loop for bulk operations |
| Users can only be found by email | there's no "list all users" by design (users are global) |
| No activity history or audit log, and no `updatedById` | planned later; log actions in the orchestrator if needed now |
| No login credentials or sessions in the data engine | auth lives in the orchestrator (planned work) |
| Memory (Qdrant) is not linked to organizations or departments yet | out of scope for these routes |

## 11. Keeping these files up to date

When the data engine's API changes:
```sh
# 1. with the data engine running locally
curl -s http://localhost:8002/openapi.json > /tmp/openapi-full.json
# 2. regenerate the reference + the domain-only contract
python3 docs/data-engine/generate.py /tmp/openapi-full.json docs/data-engine
```
`generate.py` drops the memory and MCP routes and writes `data-engine-openapi.json` and `API_REFERENCE.md`. This guide is hand-written: update it when conventions, errors or rules change.
